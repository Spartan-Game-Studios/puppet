---
title: VMC output
description: Send your tracking to other VTuber software over the VMC protocol.
---

VPuppet can send the avatar's bones and blendshapes over the **VMC protocol** (OSC over UDP) to another app, for example one that renders the avatar or a 3D scene. It's off by default.

## Set up

<Steps>
<Step>
Open **VMC** (`N`) in VPuppet. Set the receiver's **HOST** and **PORT**.

- The default, `127.0.0.1:39539`, is the usual VMC receive port (used by VSeeFace, Warudo, VNyan, VMC4U and others) on the same computer.
- For a receiver on another PC, enter that PC's local network IP address.
</Step>
<Step>
Tick **SEND VMC (OSC/UDP)** (`V`).
</Step>
<Step>
In the receiving app, enable VMC / OSC receiving on the same port, and load the same avatar there.
</Step>
</Steps>

The **TX** readout shows the frames and bytes sent. "Nothing listening" errors are counted but don't stop sending, so you can start the receiver later.

## What is sent

- **Bones:** the root and every humanoid bone, in the form receivers expect from a VRM.
- **Blendshapes:** under the model's own expression names. Preset models use the VRM 0.x names (`Blink`, `Blink_L`, `A`, `I`, `U`, `E`, `O`, `Joy`, `Angry`, `Sorrow`, `Fun`, `Surprised`...); perfect-sync models send the ARKit names.
- **ALSO SEND VRM PRESETS** (on by default): perfect-sync models also send the 13 VRM presets (`Blink`, `Blink_L`, `Blink_R`, `A`, `I`, `U`, `E`, `O`, `Joy`, `Angry`, `Sorrow`, `Fun`, `Surprised`), derived from the ARKit values, so receivers that read only presets don't see a frozen face. The ARKit values are still sent.

<Callout title="VSeeFace and perfect sync">
To use the ARKit blendshapes in VSeeFace, enable perfect sync on the receiving model there.
</Callout>

Packets are kept small enough to cross a real network, not only the local machine.

## Receive VMC (body trackers, phone apps) [#vmc-in]

VPuppet can also **receive** VMC, so body trackers or a phone app drive part of the avatar while the webcam keeps the rest.

1. In the VMC window (`N`), section **VMC IN**, tick **RECEIVE VMC**. The default port is 39539. If VPuppet's own VMC output also sends to port 39539 on this computer, give one of them another port.
2. Point the sender at this computer and port:
   - **SlimeVR:** in the SlimeVR server, turn on VMC output to `127.0.0.1` and the same port.
   - **mocopi:** send VMC from the mocopi PC link to this computer.
   - **iPhone face apps** that send VMC: tick **ALLOW OTHER DEVICES ON MY NETWORK** and send to this computer's local IP address.
3. Under **WHAT DRIVES WHAT**, choose WEBCAM or VMC for FACE, HEAD, TORSO, ARMS, FINGERS and LEGS. The default is TORSO and LEGS from VMC (body trackers), everything else from the webcam.

STATE shows RECEIVING with the rate and the sender, and GETTING shows how many bones and blend shapes arrive. If the sender stops for half a second, those body parts hand back to the webcam or the idle pose. VMC bones take priority over idle and emote animations. Blend shapes are matched by ARKit name, VRM 0.x clip name (A, Joy, Blink_L) or the model's own expression names.

No trackers yet? `node scripts/vmc-send.mjs sit` (or `walk`, `squat`, `lean`, `face`, `all`) in the source repository sends a test motion.
